# maison-x9k2m7q4 — PRIVÉE (deployed artifact)

The live PRIVÉE app: an installable, offline-capable travel and dining guide
covering 22 cities. **This repository is the build output, not the source.** The
source is `apps/privee` in the `anthropic-daily` repository, on branch
`claude/luxury-entertainment-app-h4chlk`.

Stack: node (static web app — no build step, no package manager, no dependencies)

## The one thing to know first

**A push to `main` is a live release.** GitHub Pages serves this branch directly,
and installed devices pick the change up on their next launch. There is no
staging environment. Work on a branch; merge when you mean to ship.

## Commands

- Run locally: `python3 -m http.server 8000` then open <http://localhost:8000>
  (opening `index.html` from disk does not work — it fetches JSON and registers
  a service worker, both of which need HTTP)
- Validate before publishing: `python3 tools/validate.py`
- Parse-check the shell: `python3 tools/check_syntax.py`
- Verify a deploy went live:
  `curl -s "https://mish5000.github.io/maison-x9k2m7q4/version.json?ts=$(date +%s)"`

Both checks also run in CI on every push. No install step — standard library only.

## Layout

- `index.html` — the entire app in one ~1.5 MB file. Generated; see Gotchas.
- `sw.js` — service worker (offline shell)
- `dishes.json` / `lineups.json` — venue data, regenerated by the pipeline
- `version.json` — build number the running app polls to detect a new deploy
- `assets/` — 1,997 venue photos, ~113 MB
- `tools/` — pre-publish checks
- `docs/` — ARCHITECTURE.md, DEPLOYMENT.md

## Repo etiquette

- Branch from `main`; `main` publishes
- One intent per commit. Data refreshes stay separate from shell changes.
- Never commit `.env` or `secrets/`
- `git push` asks first (see `.claude/settings.json`)

## Gotchas

These have each already cost real time.

- **Never rename this repository.** The Pages URL follows the repo name and
  GitHub does *not* redirect the old Pages path. Every installed home-screen
  icon would break. A custom domain is the prerequisite for ever changing it.
- **Never make it private.** Pages is disabled for private repos on the free
  tier — the live site would go down. This is the one repo that must stay public.
- **Don't hand-edit `index.html`.** It is generated from `apps/privee`; the next
  rebuild silently discards the edit.
- **Don't hand-edit `dishes.json` or `lineups.json`.** Same reason — the pipeline
  overwrites them.
- **Bump `version.json` when the shell changes.** The app polls it to notice a
  new deploy; without a bump nobody is prompted to reload.
- **`lineups.json` is written by a scheduled LLM Routine, not by typed code.**
  Its shape drifts. `line` has arrived as a bare string where the contract is a
  list, which threw `TypeError` and took down the whole venue sheet.
  `djTonight()` now coerces, and `tools/validate.py` fails CI on it — keep both.
- **The service worker caches hard.** A hard reload is often not enough when
  testing; unregister the worker in Safari's Web Inspector, or post it `flush`.
